## 1. Project Kickstart Prompts

Use these to instantly get a project scaffold, file structure, or feature plan for your daily challenge.

### 🚀 General Project Setup

```
I am doing Day [X] of the ABTalks 60-day challenge. Today's challenge is:
"[Challenge Title]"

Description: [Challenge Description]

Requirements:
- [Requirement 1]
- [Requirement 2]

Tech stack I want to use: [HTML/CSS/JS | React | Node.js | Python | etc.]

Please give me:
1. A recommended folder/file structure
2. A step-by-step build plan (15-minute sprints)
3. The core boilerplate code to get started immediately
```

### ⚡ Quick Feature Scaffold

```
I need to build a [feature name] in [language/framework].
It should:
- [Behavior 1]
- [Behavior 2]
- [Behavior 3]

Give me clean, production-ready code with comments explaining each section.
Keep it beginner-friendly but don't sacrifice best practices.
```

### 🎯 MVP in 1 Hour

```
I only have 1 hour to complete the ABTalks Day [X] challenge: "[Challenge Title]".
What is the absolute MVP version I should build to satisfy all requirements?
List only what's essential, what I can skip, and give me a 4-step build order.
```

## 2. Code Review & Debugging Prompts

Use these when you're stuck, getting errors, or want feedback before submitting.

### 🐛 Debugging Help

```
I'm working on the ABTalks Day [X] challenge and I have this bug:

Error message: [paste error here]

Here is the relevant code:
[paste your code here]

What is causing this error, and how do I fix it?
Explain the root cause so I can learn from it.
```

### 🔍 Code Review

```
Please review the following code I wrote for the ABTalks Day [X] challenge ("[Challenge Title]"):

[paste your code]

Review it for:
1. Bugs or edge cases I may have missed
2. Performance improvements
3. Code readability and naming
4. Security issues (if applicable)
5. Best practices I should follow

Give me specific, actionable feedback.
```

### 🧪 Write Tests

```
I built this function/component for my ABTalks Day [X] project:

[paste your code]

Write unit tests for it. Cover:
- Happy path (normal inputs)
- Edge cases (empty, null, boundary values)
- Error cases

Use [Jest / Vitest / PyTest / etc.] syntax.
```

## 3. LinkedIn Post Prompts

Use these to write your daily LinkedIn proof-of-work post — required for streak submission!

### ✍️ Standard Daily Post

```
Write a LinkedIn post about the project I built today for the ABTalks 60-day challenge.

Day: [X]
Challenge: [Challenge Title]
What I built: [Brief description of what you built]
Tech used: [List of technologies]
Key thing I learned: [Your main learning]
GitHub link: [Your GitHub URL]

Tone: Enthusiastic, honest, and educational. Use 2-3 emojis.
Include 3-5 relevant hashtags. Keep it under 250 words.
End with a question to encourage engagement.
```

### 🔥 Milestone Post (Day 7, 15, 30, 45, 60)

```
Write a LinkedIn milestone post celebrating Day [7/15/30/45/60] of the ABTalks 60-day challenge.

My progress so far:
- Days completed: [X]
- Projects built: [list a few highlights]
- Most challenging project: [title + why]
- Biggest learning: [key insight]

Make it inspiring and relatable. Show vulnerability — mention one struggle and how I overcame it.
Include stats, a story arc (struggle → learning → growth), and a call to action.
Target: 300-400 words. Use line breaks for readability.
```

### 💡 Concept Teaching Post

```
I learned about [concept/technology] while building today's ABTalks challenge.
Write a LinkedIn post where I teach this concept to other developers.

Concept: [e.g., "Intersection Observer API for infinite scroll"]
What it does: [brief explanation]
My code example: [paste your key code snippet]

Format it as a "Did you know?" or "Here's what I learned today" style post.
Use a numbered list to explain 3-5 key points. Keep it practical and code-focused.
```

### 🎤 Project Demo Post

```
Write a LinkedIn post showcasing the live demo of my ABTalks Day [X] project.

Project name: [name]
Demo link / GitHub: [link]
3 features I'm most proud of:
  1. [Feature 1]
  2. [Feature 2]
  3. [Feature 3]
One thing I'd improve with more time: [honest reflection]

Make it conversational. Avoid corporate jargon.
Write as if I'm talking to a senior dev I respect.
```

## 5. Learning & Concept Explanation Prompts

Use these to deeply understand a concept you encountered while building.

### 🧠 ELI5 (Explain Like I'm 5)

```
Explain [concept] to me as if I'm a developer who knows JavaScript basics but hasn't used it before.
Use a simple analogy, then show a minimal code example.
Concept: [e.g., "WebSockets", "Intersection Observer", "Promises vs async/await"]
```

### 📚 Deep Dive

```
I used [technology/concept] in my ABTalks Day [X] project but I don't fully understand how it works under the hood.
Explain:
1. What problem it solves
2. How it works internally (in simple terms)
3. Common mistakes developers make with it
4. When NOT to use it
5. A real-world example beyond my project
```

### 🔄 Compare and Contrast

```
I'm deciding between [Option A] and [Option B] for my ABTalks Day [X] project.
Compare them on:
- Performance
- Ease of use
- Browser/platform support
- Community/ecosystem
- Best use case

Recommend which one I should use for [my specific use case] and why.
```

## 🛠️ Pro Tips for Using AI Effectively

1. **Be specific** — always mention the challenge day, your tech stack, and your exact goal.
2. **Iterate, don't accept** — if the output isn't right, say: *"That's close, but make it simpler / use X instead of Y."*
3. **Paste real code** — AI works best when it can see your actual code, not a description of it.
4. **Ask for explanations** — end every code prompt with: *"Explain the key parts so I can understand and maintain this."*
5. **Use it for LinkedIn too** — your daily post is required for your streak. Use Section 3 every single day.
6. **Save your best prompts** — when a prompt gives great output, save it. You'll reuse it on future days.
7. **Chain prompts** — ask for the plan first, then the code, then tests. Don't try to get everything in one shot.
